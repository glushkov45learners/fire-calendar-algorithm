# fire-harmonizer v3

Гармонізація гарячих точок MODIS (Terra, Aqua) і VIIRS S-NPP для **Fire Calendar** (NASA Space Apps 2026, «Harmonization of MODIS and VIIRS Hot Spots»).

`hotspots.csv(.gz)` (контракт 1) → **`cell_day.csv.gz` + `model_meta.json`** (контракт 2) + діагностика для слайдів.

- Rust, **без жодних зовнішніх залежностей**: gzip реалізовано на чистому Rust (`src/gz.rs`), тому все однаково працює на Windows, Linux і macOS.
- Повний прогін на реальних даних (2,39 млн точок; підбір гіперпараметрів крос-валідацією + 200 bootstrap-реплік) — **~2 хв на 2 ядрах**. З `--no-tune` (готові параметри) — ~15 с, і для даних України `cell_day.csv.gz` виходить побайтово тим самим. З `--nested` (чесна оцінка) — ~14 хв.
- Покрокова інструкція для RustRover — у [RUSTROVER.md](RUSTROVER.md). Повний опис моделі — в окремому документі «Fire Calendar — модель гармонізації MODIS ↔ VIIRS, версія v3».

## Швидкий старт

```bash
cargo build --release

./target/release/harmonize --input data/hotspots.csv --out out/
./target/release/check --out out/
```

Вивантаження в бакет за контрактом:

```bash
gsutil cp out/cell_day.csv.gz out/model_meta.json gs://<bucket>/v1/model/v3/
```

### Опції `harmonize`

| Опція | Типово | Що робить |
|---|---|---|
| `--input PATH` | `hotspots.csv.gz` | `.gz`, звичайний CSV або `-` (stdin) |
| `--out DIR` | `out` | тека результатів |
| `--model-version STR` | `v3` | значення `model_version` у `model_meta.json` |
| `--no-tune` | вимк. | не підбирати гіперпараметри, а взяти вибрані на даних України 2012–2019 (див. нижче). Швидко; для іншого регіону краще з підбором |
| `--nested` | вимк. | додатково вкладена LOYO-крос-валідація — чесні метрики з урахуванням підбору параметрів |
| `--persistent-mask M:Y` | `30:8` | маска мікроклітинок ~0,005°, де детекції є в ≥ M місяцях і ≥ Y роках (заводи, факели без позначки `type` 2); `0` — вимкнути |
| `--fit-years A-B` | `2012-2019` | роки навчання (до дрейфу орбіт Terra й Aqua) |
| `--viirs-drop-low` | вимк. | не брати VIIRS `conf=l` в опорний ряд |
| `--bootstrap N` | `200` | репліки для довірчих інтервалів |
| `--gap-threshold X` | `15` | скільки точок має прогнозувати модель, щоб нуль S-NPP за добу вважався збоєм сенсора |
| `--threads N` | усі ядра | |
| `--seed N` | `42` | зерно для bootstrap (результат детермінований) |

## Модель

**Опорна шкала — VIIRS S-NPP.** З 25.01.2012 `count_h` дорівнює спостереженому S-NPP. Модель застосовується лише там, де S-NPP немає: 01.11.2000 – 24.01.2012 і 51 доба збою сенсора. Тому в сучасних даних, з якими користувач порівнює «поточний місяць», немає жодної модельної похибки. Опорний ряд не змішує S-NPP з NOAA-20 і NOAA-21, тож штучних стрибків 2018 і 2023 років немає.

Для запису «клітинка 0,1° × доба UTC × день/ніч» з `m` точками MODIS:

```
count_h = ( m · k[s] · βₛ · βₚ · βᵢ   +   a(m) · g[s] · γᵢ · γₙ · γₛ ) · c[день/ніч, місяць]
            └─ детектована частина ─┘     └──── пропущена маса ────┘
frp_h   = ( детектована · φ_det[s] · γᶠᵢ  +  пропущена · φ_miss[s] )  · c_frp[день/ніч, місяць]
```

| Член | Зміст |
|---|---|
| `s` | страта: день/ніч × місяць × [земний покрив] × просторовий блок (4°, 2°, 1° або 0,5° — глибину обирає CV) |
| `k[s]` | відношення VIIRS/MODIS у клітинко-добах, де MODIS щось бачив |
| `βₛ` | розмір події (1, 2, 3–4, 5–8, 9–16, 17+ точок MODIS): VIIRS дає більше пікселів на велику пожежу |
| `βₚ` | патерн сенсорів: лише Aqua / лише Terra / обидва (CV на даних України його вимкнула) |
| `βᵢ` | інтенсивність: середній FRP однієї детекції MODIS (терцилі) |
| `a(m)·g[s]` | **пропущена маса** — точки VIIRS у клітинко-добах, де MODIS не бачив нічого (~59 % сигналу). Розподіляється порівну на кожну клітинко-добу з MODIS у страті («присутність») |
| `γᵢ·γₙ·γₛ` | множники пропущеної маси за інтенсивністю, **сусідством** (скільки інших клітинко-діб з MODIS у вікні 3×3 клітинки × ±1 доба) і розміром події. Оцінюються EM (пуассонівська суміш) на одиницях «страта × рік» |
| `φ_det`, `φ_miss`, `γᶠᵢ` | середній FRP точки VIIRS окремо для детектованої і пропущеної частин + поправка на інтенсивність |
| `c` | калібрування сум: на навчальних роках сума прогнозу дорівнює сумі S-NPP у кожній страті «день/ніч × місяць» |

Множники β оцінюються ітеративним пропорційним підганянням (IPF) — це пуассонівська GLM `log μ = log m + α_s + βₛ + βₚ + βᵢ`.

**Стягування.** Кожен коефіцієнт страти оцінюється ієрархічно (гамма-пуассонівська оцінка):

```
k_L[s] = (ΣV + λ·k_{L−1}[parent]) / (ΣM + λ)     день/ніч → місяць → [земний покрив] → 4° → 2° → 1° → 0,5°
```

Сусідні місяці додатково згладжуються з вагою `smooth`. Мала страта «позичає силу» в батьківської, а велика живе своїми даними.

**Чому пропущена маса окремо.** Контракт пише рядок лише там, де є хоч одна точка. Для 2005 року клітинко-доба з MODIS = 0 рядка не має, тож «невидимі» дрібні пожежі розподіляються по клітинках із MODIS у тій самій страті. **Суми по полігону й місяцю (саме їх рахує API) незміщені**, а окрема клітинко-доба до 2012 року — статистична оцінка.

**Terra-only** (01.11.2000 – 03.07.2002, коли Aqua ще не було) має окрему підмодель тієї самої структури, навчену на Terra проти S-NPP: Terra пролітає о 10:30, а Aqua і S-NPP — о 13:30.

**Фільтри.**
- `type` 2/3 виключено.
- У NRT (2026 рік) `type` порожній, тому промислові джерела прибираються **маскою**: мікроклітинки 0,005° навколо SP-точок `type` 2/3, сусідство 3×3.
- Маска стабільних джерел за даними: мікроклітинки з детекціями ≥ 30 місяців і ≥ 8 років (на даних України 112 мікроклітинок, 14 тис. точок).
- Low-confidence MODIS — гіперпараметр (CV на даних України його залишила).
- Колонка `lc` (земний покрив, IGBP) необов'язкова: якщо вона є, клітинка отримує групу більшості з 6 (ліс / савани / луки / ріллі / мозаїка / інше).

### Гіперпараметри

Типово `harmonize` підбирає їх сам: покоординатний спуск, критерій — LOYO WAPE на рівні «блок 2° × місяць», потім окремо — спосіб FRP. На даних України 2012–2019 вийшло (це ж бере `--no-tune`):

| | λ | smooth | глибина | земний покрив | розмір βₛ | інтенсивність | патерн | пропущена маса | EM | FRP |
|---|---|---|---|---|---|---|---|---|---|---|
| Terra+Aqua | 100 | 0,5 | 1° | ні | так | так | ні | присутність | страта × рік | окремо дві частини |
| лише Terra | 100 | 0,25 | 2° | так | так | так | — | присутність | страта × рік | окремо дві частини |

### Валідація

- **LOYO (leave-one-year-out) на 2012–2019.** Модель навчається на 7 роках і прогнозує 8-й **лише з MODIS**. Прогноз порівнюється з **усіма** точками S-NPP, зокрема там, де MODIS не бачив нічого. Так імітується саме застосування до 2000–2011 років.
- **Метрики на агрегатах**: Україна × місяць, блок 2° × місяць, блок 1° × місяць; річні суми; сезонний профіль; підгрупи (сезон, день/ніч, земний покрив, рівень активності). MAPE — лише для одиниць зі спостереженням ≥ 20.
- **Вкладена LOYO** (`--nested`): гіперпараметри підбираються без відкладеного року — чесна оцінка всієї процедури.
- **Стрес-тест**: роки після 2019 (дрейф орбіт, війна) → `holdout_years`.
- **Інтервали**: bootstrap по роках навчання × lognormal-залишок окремого року (σ з LOYO, поправка Стьюдента на малу вибірку).

## Обмеження (є і в `notes`)

- До 2012 року клітинко-доба розріджена: на малих полігонах менше діб «з вогнем», ніж після 2012-го, хоча суми збігаються. Для малих областей календар варто показувати по тижнях.
- Тихі регіони-місяці (мало MODIS) недооцінені приблизно на 40 %: за контрактом 2 «невидимі» пожежі там нікуди покласти. Виправлення потребує зміни контракту (таблиця фону по регіону × добі).
- Нуль у `suspected_no_data_ranges` може означати «немає даних», а не «немає пожеж».
- Дрейф орбіт MODIS (Terra з 2020, Aqua з 2021): модель навчена до нього. Якщо S-NPP колись перестане працювати, заміною має стати NOAA-20 → S-NPP, а не MODIS.

## Структура

```
src/data.rs       читання контракту 1, фільтри, маски, агрегація до клітинка × доба × день/ніч
src/model.rs      ієрархія страт, сусідство, навчання (IPF, EM, стягування), прогноз
src/cv.rs         LOYO, метрики, підбір гіперпараметрів, вкладена CV, паралельність
src/main.rs       CLI, збої сенсорів, bootstrap, вихідні файли
src/gz.rs         gzip на чистому Rust (inflate + deflate, CRC32)
src/date.rs, json.rs, rng.rs   дати, запис JSON, ГПВЧ для bootstrap
src/bin/check.rs  перевірка результатів за контрактом 2
.run/             готові конфігурації запуску для RustRover
examples/         результати на даних України (model_meta, річні суми, підгрупи)
docs/history/     порівняння версій v1 → v4
```

`cargo test` запускає юніт-тести: дати, парсинг і маска NRT, метрики, gzip.
